# Защита ПР4: шпаргалка

Тема: создание датасета из открытого API GitHub и его анализ. Парная к ЛР5.

## Рассказ на минуту

Источник другой, чем в ЛР5: API поиска GitHub без авторизации. Сначала попробовал ленту публичных
событий, но без авторизации она кешируется и отдаёт максимум 300 событий. Поиск репозиториев подошёл:
30 запросов, за каждый день с 1 по 15 августа 2025 года 100 популярных и 100 обычных репозиториев.
После очистки 2978 репозиториев, 15 столбцов. Популярные лучше оформлены: лицензия, темы, описание,
больше размер, дольше развиваются. Случайный лес отличает популярный от обычного с ROC-AUC 0,80.

## Числа

- 30 запросов, пауза 7 секунд (лимит 10 в минуту), около 3,5 минуты.
- 3000 репозиториев, удалено 22 пустых, у 3 срок развития отрицательный (обрезан до нуля).
- Популярные: звёзды от 49 до 138 009, медиана 147. Обычные: по 3 звезды.
- Лицензия 73,4 % против 39,4 %, темы 44,1 % против 16,2 %, организация 30,3 % против 10,9 %.
- Размер: медиана 3667 КБ против 561. Срок развития: медиана 281 день против 27.
- Модель: лес accuracy 0,7208, ROC-AUC 0,7994; логрегрессия 0,7060 и 0,7782.
- Важность: срок развития 0,296, размер 0,211, описание 0,133, лицензия 0,129.

## Вероятные вопросы

**— Почему не лента событий, как предлагалось?**
Проверил: без авторизации заголовок X-Poll-Interval 60, два запроса через 8 секунд вернули одни и те же
100 событий, всего не больше 300. Датасет из неё не собрать.

**— Почему выборка из двух групп?**
Первая версия брала только популярные репозитории, выборка была обрезана снизу на 49 звёздах,
и модель давала ROC-AUC 0,57. Две группы делают вопрос осмысленным: чем популярный проект
отличается от обычного.

**— Почему у обычных ровно 3 звезды?**
Запрос stars:1..3 с сортировкой по совпадению вернул первыми репозитории с тремя звёздами.
Это особенность API, я её указал в отчёте.

**— Почему звёзды и форки не в признаках?**
Это следствие популярности. С ними модель подсмотрела бы ответ.

**— Нет ли подглядывания через срок развития?**
Частично есть: популярный проект чаще продолжают поддерживать. Это оговорено в отчёте.

**— Зачем пауза между запросами?**
Без авторизации поиск разрешает 10 запросов в минуту, иначе ответ 403.

## Мини-глоссарий

- **REST API**: интерфейс, где данные получают HTTP-запросами по адресам.
- **Лимит запросов (rate limit)**: сколько запросов разрешено за единицу времени.
- **Стратифицированная выборка**: набор из заранее заданных групп, здесь популярные и обычные.
