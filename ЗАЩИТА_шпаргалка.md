# Шпаргалка к защите

Тема: «Анализ данных о пассажирах авиакомпаний с использованием технологий визуализации».

## Рассказ на 30 секунд

Взял датасет Airline Passenger Satisfaction с Kaggle — 129 880 анкет пассажиров,
22 признака, задача — бинарная классификация: предсказать, удовлетворён пассажир
полётом или нет. Провёл разведочный анализ с визуализацией, обучил 4 модели
(логистическая регрессия, KNN, дерево решений, случайный лес), сравнил по 5 метрикам,
улучшил через масштабирование, отбор признаков и подбор гиперпараметров.
Лучшая модель — случайный лес: accuracy 0.963, ROC-AUC 0.994. Главные факторы
удовлетворённости — онлайн-посадка, Wi-Fi на борту, тип поездки и класс обслуживания.

## Данные — ключевые числа

- 129 880 записей (train.csv 103 904 + test.csv 25 976, объединил, чтобы самому сделать разбиение)
- 22 признака + целевая `satisfaction`; классы 56.6% «не удовлетворён» / 43.4% «удовлетворён» — почти баланс
- Пропуски только в Arrival Delay — 393 штуки (0.3%), заполнил медианой (она равна 0)
- Дубликатов нет
- Разбиение: случайное, стратифицированное, 75/25 → 97 410 обучение / 32 470 тест

**Почему случайное разбиение, а не временное?** Записи — независимые анкеты разных
людей, временной структуры нет. Временное разбиение нужно для временных рядов.
**Почему стратификация?** Чтобы доля классов в train и test была одинаковой (43.4%),
иначе оценка метрик сместится.
**Почему 75/25?** Стандарт для такого объёма: 97 тыс. хватает для обучения,
32 тыс. в тесте дают точность оценки accuracy лучше ±0.3%.

## Предобработка — что и почему

| Что сделал | Почему |
|---|---|
| Удалил `Unnamed: 0`, `id` | номер строки и ID пассажира не несут информации |
| Arrival Delay: NaN → медиана (0) | распределение задержек сильно скошено, медиана устойчивее среднего |
| Gender, Customer Type, Type of Travel → 0/1 | бинарные, порядок не важен |
| Class → 0/1/2 (Eco < Eco Plus < Business) | порядковый признак, порядок осмыслен — поэтому не one-hot |
| satisfaction → 0/1 | целевая переменная |

**Почему не one-hot?** Все категориальные признаки либо бинарные (0/1 и есть one-hot
без лишнего столбца), либо порядковые (Class — порядок важен, one-hot его потерял бы).

## Модели: почему именно эти 4

1. **Логистическая регрессия** — линейный baseline. Простейшая интерпретируемая
   модель; если сложные модели её не обгонят, они не нужны. Строит линейную
   комбинацию признаков и пропускает через сигмоиду → вероятность класса.
2. **KNN (K ближайших соседей)** — метрический метод, класс по большинству среди
   k=5 похожих пассажиров. Проверяет гипотезу «похожие пассажиры одинаково удовлетворены».
   Обучения фактически нет — запоминает выборку.
3. **Дерево решений** — нелинейная модель из правил «если оценка ≤ 3, то...».
   Интерпретируемое, не требует масштабирования.
4. **Случайный лес** — ансамбль из 100+ деревьев на бутстреп-подвыборках со случайным
   подмножеством признаков в каждом узле. Голосование деревьев снижает дисперсию →
   меньше переобучение, чем у одного дерева.

Логика набора: линейная модель + метрическая + правила + ансамбль — четыре
принципиально разных подхода.

## Метрики на моих числах (тест, 32 470 записей)

Итоговая таблица (по убыванию accuracy):

| Модель | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| Случайный лес (после подбора) | **0.9627** | 0.9720 | 0.9412 | 0.9563 | 0.9942 |
| Случайный лес (по умолчанию) | 0.9622 | 0.9719 | 0.9403 | 0.9558 | 0.9940 |
| Дерево решений | 0.9464 | 0.9377 | 0.9391 | 0.9384 | 0.9456 |
| KNN + масштабирование | 0.9283 | 0.9460 | 0.8855 | 0.9148 | 0.9705 |
| Логистическая регрессия + масштаб | 0.8747 | 0.8707 | 0.8355 | 0.8528 | 0.9275 |
| Логистическая регрессия | 0.8686 | 0.8560 | 0.8387 | 0.8472 | 0.9238 |
| KNN без масштабирования | 0.7528 | 0.7346 | 0.6747 | 0.7034 | 0.8102 |

Что означает каждая метрика **на числах леса**:

- **Accuracy 0.963** — модель верно классифицирует 96.3% пассажиров (~31 260 из 32 470).
  Адекватна, потому что классы почти сбалансированы (57/43).
- **Precision 0.972** — из тех, кого модель назвала «удовлетворён», реально
  удовлетворены 97.2%. Мало ложных срабатываний.
- **Recall 0.941** — из реально удовлетворённых модель нашла 94.1%,
  то есть ~6% удовлетворённых пропустила (пометила как недовольных).
- **F1 0.956** — гармоническое среднее precision и recall, сворачивает их в одно число.
- **ROC-AUC 0.994** — вероятность того, что случайный удовлетворённый пассажир получит
  от модели больший скор, чем случайный неудовлетворённый. 0.5 — монетка, 1.0 — идеал.
  Не зависит от порога 0.5.

У леса precision > recall: модель «осторожная» — реже ошибочно называет пассажира
довольным, но часть довольных пропускает.

## Что дала оптимизация и почему именно столько

1. **Масштабирование (StandardScaler)**:
   - KNN: 0.753 → 0.928 (**+17.5 п.п.**). Почему так много: KNN считает евклидовы
     расстояния; без масштабирования расстояние определяет Flight Distance
     (значения до 5000), а оценки сервиса (0–5) на него почти не влияют.
     После стандартизации все признаки равноправны.
   - Логистическая регрессия: 0.869 → 0.875 (+0.6 п.п.). Почему мало: линейная
     модель сама подстраивает веса под масштаб; масштабирование в основном
     улучшило сходимость оптимизатора (пропало предупреждение о несходимости).
   - Деревьям и лесу масштабирование не нужно: они сравнивают признак с порогом,
     монотонное преобразование порогов ничего не меняет.
2. **Отбор признаков**: убрал 4 признака (Gender, Gate location, Departure/Arrival
   time convenient — корреляция с целью < 0.06; Departure Delay — дублирует Arrival
   Delay, r=0.96). Accuracy леса 0.9622 → 0.9624: качество не упало, модель проще.
   Вывод: эти признаки действительно неинформативны.
3. **Подбор гиперпараметров леса** (GridSearchCV, 12 комбинаций × 3 фолда = 36 обучений;
   сетка: n_estimators 100/200, max_depth 15/25/None, min_samples_leaf 1/3):
   0.9622 → 0.9627 (**+0.05 п.п.**). Почему так мало: дефолтные параметры леса уже
   близки к оптимуму, модель упёрлась в потолок информативности признаков.
   Это честный результат, не подгонка.

## Обучение без учителя — что показало

- **PCA** до 2 компонент: объясняют только 29.4% дисперсии → данные существенно
  многомерны, на плоскости классы перемешаны.
- **K-Means** (k=2): скорректированный индекс Рэнда с реальными классами 0.28
  (1 = полное совпадение, 0 = случайность). Кластеры отражают скорее тип
  поездки/класс обслуживания, чем удовлетворённость.
- Вывод: без меток классов задача не решается → нужно обучение с учителем.

## Главные факторы удовлетворённости (важность признаков леса)

1. Online boarding (0.17) — удобство онлайн-посадки
2. Inflight wifi service (0.14)
3. Type of Travel (0.10) — деловые пассажиры довольны чаще
4. Class (0.09) — бизнес-класс доволен чаще
5. Inflight entertainment (0.06)

Практический вывод для авиакомпании: вкладываться в цифровые сервисы
(онлайн-посадка, Wi-Fi), а не в пол/возраст-таргетинг — пол вообще не влияет (важность 0.004).

## Вероятные вопросы и ответы

**— Почему не удалили выбросы в задержках (до 27 часов)?**
Это реальные события, а не ошибки измерения. Удаление исказило бы данные. Деревья
и лес устойчивы к выбросам; для чувствительных моделей применил стандартизацию.

**— Данные нормально распределены?**
Нет. Критерий Шапиро–Уилка на подвыборке 5000: p-value < 0.05 у всех количественных
признаков — все распределения не нормальные (возраст близок к симметричному, но
не гауссов; задержки экспоненциально скошены). Поэтому в анализе опирался на
медиану и квартили, а не только на среднее.

**— Что такое стратификация?**
Разбиение с сохранением доли классов: и в train, и в test по 43.4% удовлетворённых.

**— Почему у дерева ROC-AUC (0.946) намного ниже, чем у леса (0.994), хотя accuracy близки?**
Одно дерево выдаёт грубые вероятности (доли в листьях, часто 0 или 1), ранжирует
плохо. Лес усредняет 200 деревьев → гладкие вероятности → лучшее ранжирование.

**— Переобучение проверяли?**
Да: метрики считались только на отложенном тесте; гиперпараметры подбирались
кросс-валидацией внутри train; кривая обучения показывает сходимость качества
на валидации без разрыва, характерного для переобучения. Ограничение глубины
и min_samples_leaf в сетке — как раз регуляризация дерева.

**— Почему объединили train.csv и test.csv с Kaggle?**
По заданию нужно самостоятельно выполнить и обосновать разбиение. Объединил и
разбил заново стратифицированно 75/25 с фиксированным random_state=42.

**— Что такое random_state=42?**
Фиксация генератора случайных чисел для воспроизводимости: при каждом запуске
разбиение и модели идентичны. 42 — просто традиция.

**— Матрица ошибок лучшей модели?**
Из 18 363 недовольных верно распознано ~98%, из 14 107 довольных — ~94%
(830 довольных модель приняла за недовольных — это основной тип ошибки).

**— Чем ваша работа отличается от ноутбуков на Kaggle?**
Уровень метрик тот же (топ-решения 0.95–0.96), но у меня полный цикл по заданию:
описательная статистика с проверкой нормальности, обучение без учителя,
обоснование разбиения, сравнение «до/после» улучшений — и только стандартный
scikit-learn, без чёрных ящиков.

**— Перспективы?**
Градиентный бустинг (XGBoost/CatBoost — на Kaggle даёт ~0.96+), SHAP для
интерпретации, калибровка вероятностей; практически — переход от анкет к
операционным данным авиакомпании.

## Мини-глоссарий (если спросят термин)

- **Сигмоида** — функция, сжимающая любое число в (0,1); в логрегрессии превращает линейную комбинацию в вероятность.
- **Бутстреп** — случайная подвыборка с возвращением; на таких обучаются деревья леса.
- **Кросс-валидация (cv=3)** — train делится на 3 части, модель 3 раза обучается на 2/3 и проверяется на 1/3; метрика усредняется.
- **StandardScaler** — из каждого признака вычитается среднее и делится на стандартное отклонение → среднее 0, дисперсия 1.
- **Стандартизация vs нормализация** — стандартизация: к среднему 0 и дисперсии 1; нормализация (MinMax): в отрезок [0,1]. Использовал стандартизацию — устойчивее к выбросам.
- **PCA** — поворот осей в направления максимальной дисперсии; первые компоненты сохраняют максимум информации.
- **Индекс Рэнда (ARI)** — мера совпадения двух разбиений с поправкой на случайность: 1 — идентичны, 0 — как случайно.
